    8. Authentification et autorisation

    Deux questions distinctes se posent pour chaque requête :

    • qui est l'utilisateur ? C'est l'authentification : il s'est identifié par un login et un mot de passe, et chaque requête suivante doit prouver qu'elle vient de lui ;
    • a-t-il le droit d'accéder à cette page ? C'est l'autorisation : dans l'étude de cas, seul un utilisateur de rôle ADMIN gère les médecins et les clients.

    Le serveur étant sans état (chapitre sur les portées), la preuve d'identité doit voyager avec chaque requête. On utilise un jeton JWT (*JSON Web Token*) : après la connexion, le serveur fabrique un jeton qui contient l'identité de l'utilisateur et le signe avec une clé secrète. Le jeton est déposé dans un cookie ; le navigateur le renvoie à chaque requête ; le serveur vérifie la signature. L'utilisateur peut lire son jeton, mais pas le modifier : toute modification rend la signature invalide. C'est le principe de la session de [Flask] (exemple 20), mais avec un format normalisé (RFC 7519), compris par tous les langages, et une date d'expiration intégrée au jeton.

    [Flask] n'a pas de système de sécurité intégré, contrairement à [Spring] ([Spring Security]) ou [ASP.NET Core]. Des extensions existent ([Flask-Login], [Flask-JWT-Extended]...), mais le mécanisme est assez simple pour être écrit à la main, avec les outils des chapitres précédents, ce qui a l'avantage de le rendre visible :

    • l'authentification est l'affaire d'une fonction [before_request] (chapitre précédent), qui cherche le jeton dans le cookie, le vérifie, et range l'utilisateur authentifié dans [g], l'objet de la requête ;
    • l'autorisation est l'affaire de décorateurs posés sur les actions ([@connexion_requise], [@role_requis("ADMIN")]), construits comme le décorateur [@avec_langue] de l'exemple 12.

    Deux bibliothèques sont utilisées, installées par le fichier [requirements.txt] des exemples : [PyJWT], qui fabrique et vérifie les jetons, et [bcrypt], qui hache les mots de passe.

from pathlib import Path

from flask import Blueprint, Flask

from auth import securite
from auth.service import AuthService
from auth.utilisateurs import UtilisateursService
from controllers.auth import auth
from controllers.profil import profil

BOOTSTRAP = Path(__file__).resolve().parent.parent / "commun" / "bootstrap"


def create_app():
    app = Flask(__name__)
    app.jinja_env.trim_blocks = True
    app.jinja_env.lstrip_blocks = True
    # la configuration : le fichier config.py, puis les variables d'environnement
    # qui commencent par FLASK_ (FLASK_JWT_SECRET remplace JWT_SECRET)
    app.config.from_pyfile("config.py")
    app.config.from_prefixed_env()
    # les services de l'authentification
    utilisateurs = UtilisateursService()
    app.extensions["auth"] = AuthService(utilisateurs, app.config["JWT_SECRET"],
                                         app.config["JWT_DUREE_MINUTES"])
    app.register_blueprint(Blueprint("bootstrap", __name__, static_folder=BOOTSTRAP,
                                     static_url_path="/bootstrap"))
    app.register_blueprint(auth)
    app.register_blueprint(profil)
    # l'utilisateur de chaque requête, lu dans le jeton du cookie
    securite.enregistrer(app)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)

La valeur d'une variable est interprétée comme du JSON quand c'est possible ([FLASK_JWT_DUREE_MINUTES=30] donne l'entier 30). En production, la clé secrète est fournie par l'environnement, et le fichier ne contient qu'une valeur de développement ;
    • lignes 24-26 : les deux services de l'authentification, dont le second reçoit la clé et la durée de vie des jetons ;
    • ligne 32 : l'enregistrement de la fonction [before_request] qui lit le jeton.

from dataclasses import dataclass

import bcrypt


@dataclass(frozen=True)
class Utilisateur:
    login: str
    nom: str
    role: str
    hachage_mot_de_passe: bytes


# le hachage d'un mot de passe : bcrypt, avec un coût de 10 (2^10 tours) ;
# gensalt tire un "sel" aléatoire, qui est rangé dans le hachage lui-même
def hacher(mot_de_passe: str) -> bytes:
    return bcrypt.hashpw(mot_de_passe.encode(), bcrypt.gensalt(rounds=10))


class UtilisateursService:

    def __init__(self):
        # on ne conserve JAMAIS un mot de passe, seulement son hachage
        self._utilisateurs = {u.login: u for u in (
            Utilisateur("marie", "Marie Pélissier", "USER", hacher("marie")),
            Utilisateur("admin", "Administrateur", "ADMIN", hacher("admin")),
        )}

    def chercher(self, login: str) -> Utilisateur | None:
        return self._utilisateurs.get(login)
    • lignes 9-13 : un utilisateur : son login, son nom, son rôle, et le hachage de son mot de passe. Un serveur ne conserve jamais un mot de passe, même chiffré : si la base de données était volée, les mots de passe le seraient aussi (et beaucoup de gens utilisent le même partout). Il conserve le résultat d'une fonction de hachage, une fonction à sens unique : on peut calculer le hachage d'un mot de passe, mais pas retrouver un mot de passe à partir de son hachage. Pour vérifier un mot de passe saisi, on calcule son hachage, et on le compare à celui qui est enregistré ;
    • lignes 18-19 : le hachage par l'algorithme [bcrypt], conçu pour les mots de passe. Il a deux particularités. Il est volontairement lent, d'une lenteur réglable (le paramètre [rounds], ou coût : 2^10 tours de calcul) : quelques dizaines de millisecondes, imperceptibles pour un utilisateur, mais qui rendent très coûteux l'essai de milliards de mots de passe par un pirate. Il est salé : [gensalt] tire au hasard un sel, mélangé au mot de passe avant hachage, et rangé dans le hachage lui-même ; deux utilisateurs qui ont le même mot de passe ont ainsi des hachages différents. [bcrypt] travaille sur des octets : [encode()] convertit la chaîne en octets ([UTF-8]). Il ne prend en compte que les 72 premiers octets d'un mot de passe, et la version 5 de la bibliothèque refuse un mot de passe plus long (l'étude de cas en tient compte) ;
    • lignes 26-28 : deux utilisateurs de test, en mémoire, rangés dans un dictionnaire construit en compréhension ([{clé: valeur for ...}]). L'exemple 28 et l'étude de cas les mettront dans une base de données.

    # auth/service.py : la vérification des mots de passe et les jetons JWT
from datetime import datetime, timedelta, timezone

import bcrypt
import jwt
from flask import current_app

from auth.utilisateurs import Utilisateur, UtilisateursService

# le nom du cookie qui transporte le jeton
COOKIE = "jeton"


class AuthService:

    def __init__(self, utilisateurs: UtilisateursService, secret: str, duree_minutes: int):
        self._utilisateurs = utilisateurs
        self._secret = secret
        self.duree = timedelta(minutes=duree_minutes)

    # l'utilisateur, ou None si le login est inconnu ou le mot de passe faux.
    # checkpw hache le mot de passe saisi avec le sel du hachage enregistré,
    # puis compare les deux résultats
    def valider(self, login: str | None, mot_de_passe: str | None) -> Utilisateur | None:
        if not login or mot_de_passe is None:
            return None
        utilisateur = self._utilisateurs.chercher(login)
        if utilisateur is None or not bcrypt.checkpw(mot_de_passe.encode(),
                                                     utilisateur.hachage_mot_de_passe):
            return None
        return utilisateur

    # le jeton JWT de l'utilisateur, signé avec la clé secrète (HMAC-SHA256)
    def creer_jeton(self, utilisateur: Utilisateur) -> str:
        maintenant = datetime.now(timezone.utc)
        # le contenu du jeton : les "claims" (affirmations sur l'utilisateur)
        claims = {
            "sub": utilisateur.login,
            "nom": utilisateur.nom,
            "role": utilisateur.role,
            "iat": maintenant,
            "exp": maintenant + self.duree,
        }
        return jwt.encode(claims, self._secret, algorithm="HS256")

    # les claims d'un jeton dont la signature et la date d'expiration sont
    # valides ; None sinon (jeton falsifié, expiré ou illisible)
    def verifier(self, jeton: str) -> dict | None:
        try:
            return jwt.decode(jeton, self._secret, algorithms=["HS256"])
        except jwt.InvalidTokenError:
            return None


def auth_service() -> AuthService:
    return current_app.extensions["auth"]
    • lignes 24-31 : la vérification d'un login et d'un mot de passe. [bcrypt.checkpw] hache le mot de passe saisi avec le sel du hachage enregistré, et compare les deux hachages. Un login inconnu et un mot de passe faux donnent le même résultat, [None] ;
    • lignes 34-44 : la fabrication du jeton. Son contenu est un dictionnaire d'affirmations (*claims*) sur l'utilisateur. Certaines ont un nom normalisé : [sub] (*subject*), l'identifiant de l'utilisateur ; [iat] (*issued at*), la date de création ; [exp] (*expiration*), la date d'expiration. Les autres sont libres : ici le nom et le rôle. [jwt.encode] fabrique le jeton et le signe avec l'algorithme [HS256] (HMAC-SHA256, une signature par clé secrète partagée). Les dates doivent être des dates avec fuseau horaire : [datetime.now(timezone.utc)] ;
    • lignes 48-30 : la vérification d'un jeton. [jwt.decode] vérifie la signature et la date d'expiration, puis rend les affirmations. Toute anomalie (jeton falsifié, expiré, mal formé) lève une exception de la famille [InvalidTokenError]. Le paramètre [algorithms] fixe les algorithmes acceptés : sans lui, un pirate pourrait fabriquer un jeton qui déclare un autre algorithme (voire aucun, [none]).

    # auth/securite.py : l'utilisateur de chaque requête, et la protection des actions
from functools import wraps

from flask import g, redirect, request, url_for

from auth.service import COOKIE, auth_service


def enregistrer(app):

    # avant chaque action : le jeton du cookie -> g.utilisateur (ses claims), ou None
    @app.before_request
    def lire_jeton():
        jeton = request.cookies.get(COOKIE)
        g.utilisateur = auth_service().verifier(jeton) if jeton else None


# un décorateur : l'action n'est exécutée que pour un utilisateur authentifié ;
# sinon, direction la page de connexion
def connexion_requise(action):
    @wraps(action)
    def action_protegee(*args, **kwargs):
        if g.utilisateur is None:
            reponse = redirect(url_for("auth.formulaire"))
            # un cookie présent mais invalide (jeton expiré, falsifié) : on l'efface
            if COOKIE in request.cookies:
                reponse.delete_cookie(COOKIE)
            return reponse
        return action(*args, **kwargs)

    return action_protegee
    • lignes 13-15 : avant chaque action, le jeton du cookie est vérifié ; [g.utilisateur] contient les affirmations d'un jeton valide, ou [None]. Cette fonction ne refuse rien : elle établit qui est l'utilisateur. C'est l'authentification ;
    • lignes 20-31 : le décorateur qui exige un utilisateur authentifié. Pour un visiteur anonyme, il ne rend pas l'action, mais une redirection vers la page de connexion. Si le navigateur a envoyé un cookie, c'est que son jeton est invalide (expiré ou falsifié) : on en profite pour l'effacer ([delete_cookie] envoie un cookie vide, déjà expiré).

    # controllers/auth.py : connexion et déconnexion
from flask import Blueprint, redirect, render_template, request, url_for

from auth.service import COOKIE, auth_service

auth = Blueprint("auth", __name__)


@auth.get("/")
def accueil():
    return redirect(url_for("profil.afficher"))


@auth.get("/login")
def formulaire():
    return render_template("auth/login.html")


@auth.post("/login")
def connexion():
    login = request.form.get("login")
    utilisateur = auth_service().valider(login, request.form.get("motDePasse"))
    if utilisateur is None:
        # un message volontairement vague : on ne dit pas si c'est le login ou le mot de passe
        return render_template("auth/login.html", login=login,
                               erreur="Login ou mot de passe incorrect.")
    reponse = redirect(url_for("profil.afficher"))
    # le jeton, dans un cookie : le JavaScript de la page ne peut pas le lire
    # (httponly) ; il n'accompagne pas les requêtes POST venues d'autres sites
    # (samesite) ; il disparaît en même temps que le jeton expire (max_age)
    reponse.set_cookie(COOKIE, auth_service().creer_jeton(utilisateur), httponly=True,
                       samesite="Lax", max_age=auth_service().duree)
    return reponse


# la déconnexion : POST seulement (un simple lien, placé sur un autre site, ne
# peut pas déconnecter l'utilisateur à son insu) ; on efface le cookie
@auth.post("/logout")
def deconnexion():
    reponse = redirect(url_for("auth.formulaire"))
    reponse.delete_cookie(COOKIE)
    return reponse
    • lignes 20-26 : la connexion. En cas d'échec, le formulaire est réaffiché avec le login saisi et un message volontairement vague : dire « login inconnu » apprendrait à un pirate quels logins existent ;
    • lignes 27-32 : en cas de succès, le jeton est déposé dans un cookie, avec une redirection vers la page protégée (schéma PRG). Le cookie est [httponly] : le [JavaScript] de la page ne peut pas le lire, ce qui protège le jeton contre une injection de script (XSS) ; il est [samesite="Lax"] : le navigateur ne l'envoie pas avec une requête POST venue d'un autre site, ce qui protège l'application contre les attaques CSRF (exemple 18) ; sa durée de vie ([max_age], qui accepte un [timedelta]) est celle du jeton. En production, sur HTTPS, on ajouterait [secure=True] : le cookie ne serait jamais envoyé sur une connexion non chiffrée ;
    • lignes 38-41 : la déconnexion efface le cookie. C'est une action POST : un simple lien vers [/logout], placé sur un autre site ou dans une image, ne peut pas déconnecter l'utilisateur à son insu. Remarquons une limite des jetons : le jeton lui-même reste valide jusqu'à son expiration. Quelqu'un qui en aurait fait une copie pourrait encore s'en servir. C'est pourquoi on limite leur durée de vie.

def connexion_requise(action):
    @wraps(action)
    def action_protegee(*args, **kwargs):
        if g.utilisateur is None:
            reponse = redirect(url_for("auth.formulaire"))
            # un cookie présent mais invalide (jeton expiré, falsifié) : on l'efface
            if COOKIE in request.cookies:
                reponse.delete_cookie(COOKIE)
            return reponse
        return action(*args, **kwargs)

    return action_protegee

        def action_protegee(*args, **kwargs):
            if g.utilisateur["role"] != role:
                abort(403)  # accès refusé
            return action(*args, **kwargs)

        return action_protegee

    return decorateur

def texte_aleatoire(longueur: int) -> str:
    return "".join(_hasard.choice(ALPHABET) for _ in range(longueur))


def hasard(minimum: float, maximum: float) -> float:
    return _hasard.uniform(minimum, maximum)


def couleur() -> str:
    return _hasard.choice(COULEURS)


def svg(texte: str) -> str:
    morceaux = [f'<svg xmlns="http://www.w3.org/2000/svg" width="{LARGEUR}" height="{HAUTEUR}" '
                f'viewBox="0 0 {LARGEUR} {HAUTEUR}">',
                '<rect width="100%" height="100%" fill="#f5f7fa"/>']

    # les caractères : chacun agrandi, penché, décalé, et chaque point
    # légèrement déplacé au hasard
    pas = (LARGEUR - 20) / len(texte)
    for i, caractere in enumerate(texte):
        echelle = hasard(4.6, 5.6)  # taille d'une unité de la grille, en pixels
        angle = hasard(-0.35, 0.35)  # rotation, en radians (environ ±20°)
        cx = 10 + pas * (i + 0.5) + hasard(-3, 3)  # centre du caractère
        cy = HAUTEUR / 2 + hasard(-4, 4)
        d = []
        for trait in POLICE[caractere]:
            for k in range(0, len(trait), 2):
                # point de la grille, centré sur (2, 3), déformé, tourné, placé
                x = (trait[k] - 2 + hasard(-0.2, 0.2)) * echelle
                y = (trait[k + 1] - 3 + hasard(-0.2, 0.2)) * echelle
                px = cx + x * math.cos(angle) - y * math.sin(angle)
                py = cy + x * math.sin(angle) + y * math.cos(angle)
                d.append(f"{'M' if k == 0 else 'L'}{px:.1f} {py:.1f}")
        morceaux.append(f'<path d="{" ".join(d)}" fill="none" stroke="{couleur()}" '
                        f'stroke-width="{hasard(2.2, 3):.1f}" stroke-linecap="round" '
                        f'stroke-linejoin="round"/>')

    # 3 traits de brouillage : des courbes qui traversent l'image
    for _ in range(3):
        morceaux.append(
            f'<path d="M{hasard(0, 20):.1f} {hasard(5, 45):.1f} '
            f'C{hasard(30, 60):.1f} {hasard(0, 50):.1f} {hasard(90, 120):.1f} {hasard(0, 50):.1f} '
            f'{hasard(130, 150):.1f} {hasard(5, 45):.1f}" fill="none" stroke="{couleur()}" '
            f'stroke-width="1.3"/>')
    morceaux.append("</svg>")
    return "".join(morceaux)

import secrets
from dataclasses import dataclass
from datetime import datetime, timedelta
from threading import Lock

from flask import current_app

from auth import dessin_captcha

DUREE_VIE = timedelta(minutes=10)


# un captcha : son identifiant, et son image (SVG)
@dataclass(frozen=True)
class Captcha:
    id: str
    svg: str


class CaptchaService:

    def __init__(self):
        # identifiant -> (réponse attendue, date d'expiration)
        self._en_attente: dict[str, tuple[str, datetime]] = {}
        self._verrou = Lock()

    def generer(self) -> Captcha:
        texte = dessin_captcha.texte_aleatoire(5)
        id = secrets.token_urlsafe(16)  # un identifiant aléatoire, impossible à deviner
        with self._verrou:
            self._en_attente[id] = (texte, datetime.now() + DUREE_VIE)
        return Captcha(id, dessin_captcha.svg(texte))

    # le captcha est CONSOMMÉ dans tous les cas : une image ne sert qu'une fois
    def verifier(self, id: str | None, saisie: str | None) -> bool:
        with self._verrou:
            attendu = self._en_attente.pop(id, None) if id else None
        if attendu is None or saisie is None:
            return False
        texte, expire = attendu
        return expire > datetime.now() and texte.lower() == saisie.strip().lower()


def captcha_service() -> CaptchaService:
    return current_app.extensions["captchas"]
    • lignes 28-33 : un nouveau captcha : un texte aléatoire, un identifiant aléatoire et impossible à deviner ([secrets.token_urlsafe]), et le dessin.     • lignes 36-42 : la vérification. [pop] retire l'entrée du dictionnaire et la rend : le captcha est consommé dans tous les cas, réussi ou non. Sans cela, un programme pourrait essayer toutes les réponses sur une même image. La comparaison ignore la casse et les espaces autour de la saisie.

class Compteur:

    def __init__(self):

            compteur = self._compteurs.get(ip)
            if compteur is None:
                return 0
            reste = (compteur.bloque_jusqua - datetime.now()).total_seconds()
            return max(0, math.ceil(reste))

    def echec(self, ip: str):
        with self._verrou:
            compteur = self._compteurs.setdefault(ip, Compteur())
            compteur.echecs += 1
            if compteur.echecs >= MAX_ECHECS:
                compteur.bloque_jusqua = datetime.now() + DUREE_BLOCAGE
                compteur.echecs = 0  # après le blocage, on repart de zéro

    def reussite(self, ip: str):
        with self._verrou:
            self._compteurs.pop(ip, None)


def limiteur_service() -> LimiteurService:
    return current_app.extensions["limiteur"]
    • lignes 12-15 : pour chaque adresse IP, un nombre d'échecs et une date de fin de blocage ([datetime.min], la plus petite date possible, signifie « pas bloquée ») ;
    • lignes 26-32 : le nombre de secondes de blocage restantes, arrondi à l'entier supérieur ([math.ceil]) ;
    • lignes 34-40 : un échec de plus. [setdefault] rend le compteur de l'adresse, en le créant s'il n'existe pas. Au troisième échec, l'adresse est bloquée pour une minute, et le compteur repart de zéro ;
    • lignes 42-44 : une connexion réussie efface le compteur.

from flask import Blueprint, redirect, render_template, request, url_for

from auth.captcha import captcha_service
from auth.limiteur import limiteur_service
from auth.service import COOKIE, auth_service

auth = Blueprint("auth", __name__)


@auth.get("/")
def accueil():
    return redirect(url_for("profil.afficher"))


@auth.get("/login")
def formulaire():
    return page_login()


@auth.post("/login")
def connexion():
    login = request.form.get("login")
    # l'adresse IP du client
    ip = request.remote_addr

    # 1. une adresse bloquée n'est même pas écoutée
    secondes = limiteur_service().secondes_blocage(ip)
    if secondes > 0:
        return page_login(login, f"Trop de tentatives : réessayez dans {secondes} s.")
    # 2. le captcha d'abord (peu coûteux), le mot de passe (bcrypt, coûteux) ensuite
    if not captcha_service().verifier(request.form.get("captchaId"), request.form.get("captcha")):
        limiteur_service().echec(ip)
        return page_login(login, "Le code de l'image est incorrect.")
    utilisateur = auth_service().valider(login, request.form.get("motDePasse"))
    if utilisateur is None:
        limiteur_service().echec(ip)
        return page_login(login, "Login ou mot de passe incorrect.")
    limiteur_service().reussite(ip)
    reponse = redirect(url_for("profil.afficher"))
    reponse.set_cookie(COOKIE, auth_service().creer_jeton(utilisateur), httponly=True,
                       samesite="Lax", max_age=auth_service().duree)
    return reponse


@auth.post("/logout")
def deconnexion():
    reponse = redirect(url_for("auth.formulaire"))
    reponse.delete_cookie(COOKIE)
    return reponse


# chaque affichage du formulaire fabrique un NOUVEAU captcha
def page_login(login: str | None = None, erreur: str | None = None):
    return render_template("auth/login.html", login=login, erreur=erreur,
                           captcha=captcha_service().generer())
